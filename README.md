# 🔍 Research Agent

**Go · Gemini · Tavily · Exa · Semantic Scholar**

주제 입력부터 자료 조사, 리포트 작성, 카드뉴스 생성까지 자동화하는 리서치 에이전트입니다.

**Gemini가 조사 계획과 목표를 수립하고, 검색 결과를 평가해 추가 검색 여부와 다음 검색 도구를 결정합니다.** Tavily, Exa, Semantic Scholar를 조사 목적에 맞게 활용하며, 사용자가 리포트를 검토한 뒤 카드뉴스 생성 여부를 결정하는 Human-in-the-loop 구조를 적용했습니다.

## ✨ 핵심 기능

### 1. 조사 계획 수립 및 동적 검색

- Gemini가 조사 주제를 분석해 초기 검색 계획과 조사 목표를 수립합니다.
- 조사 목적에 따라 Tavily, Exa, Semantic Scholar 중 적합한 Tool을 선택합니다.
- 검색 결과의 출처 수, 품질 점수, 최신성, 통계 및 논문 포함 여부를 평가합니다.
- 부족한 정보를 바탕으로 다음 검색 Tool과 쿼리를 결정합니다.
- 최대 검색 횟수를 제한해 불필요한 반복 검색을 방지합니다.

### 2. 목적별 검색 Tool 활용

| Tool | 주요 역할 | 활용 분야 |
|---|---|---|
| **Tavily** | 웹 정보 검색 | 최신 동향, 뉴스, 공식 자료, 통계, 기업 도입 사례 |
| **Exa** | 의미 기반 검색 | 관련 기술, 유사 프로젝트, 새로운 접근법, 구현 사례 |
| **Semantic Scholar** | 학술 논문 검색 | 논문 초록, 저자, 출판 연도, 인용 횟수 등 연구 자료 |

각 Tool의 특성을 고려해 검색 전략을 구성하고, 모든 Tool을 무조건 사용하는 대신 조사 목적과 부족한 정보에 따라 필요한 검색을 수행합니다.

### 3. 검색 결과 필터링

- 사전에 정의한 차단 도메인으로 개인 블로그 및 커뮤니티 등 조사에 부적합한 출처를 필터링합니다.
- 검색 결과의 중복을 제거해 자료의 다양성을 확보합니다.
- 검색 결과의 품질과 조사 목표 충족 여부를 평가해 추가 검색에 활용합니다.

> 검색 API가 제공하는 점수와 논문 인용 횟수 기반 점수는 의미가 다르므로, 이를 동일한 품질 지표로 해석할 때는 주의가 필요합니다.

### 4. 리포트 자동 생성

- 검색 결과를 종합해 Markdown 형식의 리포트를 생성합니다.
- 자료의 핵심 내용과 출처 URL을 포함해 후속 검토가 가능하도록 합니다.

### 5. Human-in-the-loop 기반 카드뉴스 생성

- 생성된 리포트를 사용자가 먼저 검토합니다.
- 사용자가 승인하면 리포트의 핵심 내용을 추출해 카드뉴스를 생성합니다.
- 자료 조사 및 콘텐츠 생성 자동화에 사람의 검토 단계를 결합합니다.

### 6. Goroutine 기반 병렬 처리

- Go의 Goroutine과 Worker Pool을 활용해 여러 검색 쿼리를 병렬 처리합니다.
- Worker 수에 따른 실행 시간과 메모리 사용량을 비교해 병렬 처리 설정을 검증했습니다.

### Agent 실행 흐름

1. **Plan:** 조사 주제에 적합한 초기 검색 Tool, 쿼리 및 조사 목표를 설정합니다.
2. **Search:** 선택한 Tool로 자료를 검색하고 결과를 통합합니다.
3. **Evaluate:** 출처 수, 품질 점수, 최신성, 통계 및 논문 포함 여부를 평가합니다.
4. **Decide:** 부족한 정보를 바탕으로 추가 검색할 Tool과 쿼리 또는 종료 여부를 결정합니다.
5. **Repeat:** 조사 목표를 충족하거나 최대 검색 횟수에 도달할 때까지 검색과 평가를 반복합니다.
6. **Report:** 수집한 자료를 종합해 리포트를 작성합니다.
7. **Human Review:** 사용자가 리포트를 검토하고 승인하면 카드뉴스를 생성합니다.

## 🛠️ 기술 스택

| 기술 | 활용 |
|---|---|
| **Go** | Agent 로직 및 검색 워크플로우 구현 |
| **Gemini API** | 조사 계획 수립, 다음 행동 결정, 리포트 및 카드뉴스 콘텐츠 생성 |
| **Tavily API** | 최신 웹 자료 및 공식 정보 검색 |
| **Exa API** | 의미 기반 웹 검색 및 관련 사례 탐색 |
| **Semantic Scholar API** | 학술 논문 및 연구 메타데이터 검색 |
| **Goroutine** | 검색 쿼리의 병렬 처리 |
| **Channel / Worker Pool** | 작업 분배 및 병렬 검색 결과 수집 |
| **JSON** | Agent의 계획 및 행동 응답 구조화 |
| **HTML / CSS** | 카드뉴스 콘텐츠 표현 |

### 주요 설계 결정

- **목적 기반 Tool 선택:** 조사 주제에 가장 적합한 검색 Tool부터 사용하고, 결과 평가에 따라 후속 검색을 결정합니다.
- **동적 검색 전략:** 사전에 정해진 검색 순서를 무조건 따르지 않고, 부족한 정보에 따라 다음 행동을 선택합니다.
- **검색과 품질 평가의 분리:** 자료 수집과 결과 평가를 구분해 조사 목표 충족 여부를 판단합니다.
- **Human-in-the-loop:** 리포트 검토 후 카드뉴스를 생성하도록 해 사용자가 최종 콘텐츠 생성 과정에 참여합니다.
- **병렬 처리:** Goroutine을 이용해 독립적인 검색 작업을 동시에 수행합니다.

## 📊 성능 실험

### Worker 수에 따른 병렬 처리 성능

Tavily 단일 검색 Tool을 사용한 기존 실험에서 Worker 수를 변경하며 여러 주제의 실행 시간과 메모리 사용량을 비교했습니다.

아래는 네 가지 검색 주제 중 `Go 언어의 장점`을 대상으로 측정한 결과입니다.

| Worker 수 | 실행 시간 | 순차 대비 | 메모리 사용량 |
|---:|---:|---:|---:|
| 1 (순차) | 19,541ms | 기준 | 0.45MB |
| 2 | 611ms | 32.0배 | 0.22MB |
| 3 | 406ms | 48.1배 | 0.22MB |
| 4 | 407ms | 48.0배 | 0.22MB |
| 6 | 204ms | 95.8배 | 0.22MB |

**실험 결과**
- Worker 수를 1개에서 6개로 늘렸을 때 해당 실험의 실행 시간은 약 19.5초에서 0.2초로 감소했습니다.
- Worker 3개와 4개의 실행 시간은 비슷했으며, Worker 6개에서는 더 짧은 실행 시간이 측정됐습니다.
- Worker 수에 따른 실행 시간과 메모리 사용량을 비교해 병렬 처리 설정을 검증했습니다.

> **측정 범위:** 위 결과는 Tavily 단일 Tool을 사용한 기존 병렬 처리 실험입니다. Tavily·Exa·Semantic Scholar를 통합한 현재 동적 검색 워크플로우 전체의 처리 시간과는 구분해야 합니다. 새로운 구조의 전체 성능은 별도 측정이 필요합니다.

## 🚀 시작하기

### 1. 사전 준비

다음 항목을 준비합니다.

- Go 개발 환경
- Gemini API Key
- Tavily API Key
- Exa API Key
- Semantic Scholar API 사용 환경

각 API의 발급 및 이용 조건은 해당 서비스의 공식 문서를 확인하세요.

- [Google AI Studio](https://aistudio.google.com/)
- [Tavily](https://tavily.com/)
- [Exa](https://exa.ai/)
- [Semantic Scholar API](https://api.semanticscholar.org/)

### 2. 환경 변수 설정

사용 중인 코드에서 읽는 환경 변수 이름에 맞춰 API Key를 설정합니다.

```bash
export GEMINI_API_KEY="your_gemini_api_key"
export TAVILY_API_KEY="your_tavily_api_key"
export EXA_API_KEY="your_exa_api_key"
```

> API Key는 소스 코드나 GitHub 저장소에 직접 입력하지 마세요.

### 3. 프로젝트 실행

```bash
git clone https://github.com/<username>/<repository>.git
cd <repository>

go mod download
go run .
```

`<username>`과 `<repository>`는 실제 GitHub 저장소 정보로 변경합니다.

### 4. 리서치 실행

프로그램을 실행한 뒤 조사할 주제를 입력합니다.

예시:

```text
조사 주제: AI Coding Agent의 기술과 개발 방식 변화
```

Agent는 다음 순서로 동작합니다.

```text
조사 계획 수립
    ↓
초기 Tool 선택 및 검색
    ↓
검색 결과 평가
    ↓
추가 검색 여부 결정
    ↓
리포트 생성
    ↓
카드뉴스 생성 여부 확인
```

실제 콘솔 출력과 실행 메뉴는 현재 구현된 CLI에 맞춰 확인해 주세요.
